# Gravity Relay 무한 진행

## 플레이 흐름

GravityRelay 씬을 열고 Play. 시작 행성 → 위쪽 목표 → 다시 위쪽 목표 순서로 계속 진행한다. 점수는 착륙 완료마다 +1, 목표 번호는 2, 3, 4…로 증가한다. 기존 3→1 복귀는 없어진다. R 또는 실패 후 클릭/터치로 새 게임을 시작하면 행성·카메라·점수·시드가 함께 초기화된다.

기존 물리 기준값(발사 15, 중력 60, 상한 40, 공전 150, 포획 여유 0.30, 보정 0.06초)을 유지한다. 손맛과 비교 프리셋은 Docs/GravityRelayBalance.md 참고.

## 행성 생성과 회수

Endless Course 오브젝트의 Relay Endless Course가 원래 세 행성을 템플릿으로 사용한다. 최초 시작 시 총 8개의 풀을 구성하고 이후에는 회수한 행성을 재사용한다. 재시작 때 새로 늘리지 않는다. 현재 행성과 다음 목표는 회수하지 않는다. 과거 행성은 포획 링까지 포함한 위쪽 끝이 화면 아래보다 1 unit 더 내려갔을 때 비활성화한다.

- 시작 위치 (-1,-3.2), 첫 목표 (1,0). 기본 배치와 익숙한 첫 이동을 유지한다.
- 다음 목표는 현재 행성보다 3.1~3.7 units 위, x=-1.6~1.6에서 생성한다.
- 활성 행성의 포획 반경끼리도 최소 0.15 units 여유를 두어 겹치지 않게 한다.
- seed=2718. 재시작은 같은 코스를 재현하고 Unity의 전역 Random 상태는 바꾸지 않는다.
- 최대 10개 무작위 후보와 9개 제한 범위 내 대체 후보를 검사한다. 무한 재시도는 하지 않는다.
- 현재 공전 방향/각도와 실제 FixedUpdate 간격에서 발사 타이밍을 샘플링한다. 런타임 비행과 같은 중력 적분·이동 선분 포획 검사·시간 제한·화면 경계로 도달 가능성을 확인한다. 세 샘플 연속 성공하는 후보만 사용한다. 기본값에서는 인접한 세 고정 틱에 해당한다.
- 사용자 설정 때문에 후보가 모두 불가능하거나 풀이 부족하면 잘못된 목표를 강제로 내놓지 않고 NO REACHABLE ROUTE로 종료한다. 기본 물리와 배치 범위를 한 묶음으로 조정해야 한다.

## 카메라와 실패 조건

공전 중 카메라는 현재 행성보다 3.2 units 위를 중앙으로 삼아 부드럽게 이동한다. 프레임률에 의존하지 않는 지수 보간을 고정 간격에서 적용한다. 목표 위치에 도착하기 전에는 발사 화살표를 숨기고 FRAMING NEXT ORBIT...를 표시하며 발사를 받지 않는다. 공전 자체는 계속한다.

발사 시 화면의 월드 경계를 저장한다. Flying/Capturing/Dead 동안 카메라 추적을 멈추고, 발사 때 저장한 경계로 화면 이탈을 판정한다. 따라서 카메라가 캐릭터를 계속 쫓아가 화면 이탈 실패가 사라지는 문제가 없다. 착륙 완료 후 다음 구간으로 다시 이동한다.

## Inspector (Endless Course > Relay Endless Course)

|항목|기본값|역할|
|---|---:|---|
|Seed|2718|재현 가능한 생성 순서|
|Start Position|(-1,-3.2)|재시작 위치|
|Pool Size|8|원본 포함 총 행성 수, 8~12|
|Min / Max Vertical Gap|3.1 / 3.7|다음 목표의 높이 차|
|Horizontal Limit|1.6|좌우 생성 범위 절댓값|
|Separation Margin|0.15|포획 반경 사이 여유|
|Candidate Attempts|10|무작위 후보 시도 상한|
|Camera Look Ahead|3.2|현재 행성 대비 화면 중심 높이|
|Camera Sharpness|12|높일수록 빠르게 다음 구간을 비춤|
|Retire Margin|1|화면 아래로 충분히 벗어난 행성만 회수|

고정된 물리값과 세로 9:16, 직교 크기 8을 기준으로 한다. 먼저 기본 범위를 사용한 뒤 한 항목씩 바꾼다. 과도한 반경/간격 변경은 도달 가능한 후보를 없앨 수 있다.

Play 중 물리/생성 설정을 바꿨다면 재시작해서 새 설정으로 목표 도달 가능성을 다시 검사한다. 이미 생성된 목표는 생성 당시 물리값으로 검증된 것이다.

## 확인 방법

1. Play 후 금색 목표가 위쪽에 있는지, 3번째 이후에도 위로 이어지는지 확인.
2. 착륙 후 카메라 이동 → 화살표 표시 → 다음 발사가 이어지는지 확인.
3. 비행 중 카메라가 멈추고, 반대 방향으로 잘못 쏘면 화면 밖에서 실패하는지 확인.
4. Hierarchy에서 행성 수가 일정하고, 아래로 멀어진 행성만 재사용되는지 확인.
5. 여러 번 착륙한 뒤 R로 재시작해 점수/목표/행성 배치/카메라가 처음으로 돌아오는지 확인.

Gravity Relay > Validate Endless Progression은 편집 씬을 움직이지 않고 임시 복제본에서 현재 물리값으로 100회 착륙, 카메라 잠금, 위쪽 목표, 풀 개수, 비겹침, 재시작, 화면 이탈, 시간 초과를 검사한다. Validate Movement 메뉴도 무한 진행이 연결된 씬에서는 이 검사로 연결된다. 실제 기기 입력/시각 품질 검사는 별도다.

## 2026-10-30 확인 결과

- Unity 6000.3.25f1에서 컴파일하고 기존 씬에 Endless Course 참조를 연결/저장했다. 물리 기준값은 변경하지 않았다.
- 기본 seed=2718 검사에서 100회 연속 착륙, 위쪽 목표, 비행/포획 중 카메라 정지, 활성 행성 비겹침, 풀 유지(총 8개·활성 최대 5개), 재시작, 화면 이탈, 시간 초과를 모두 통과했다.
- 실제 Play에서 시작 화면/공전/목표 링/점수 표시, 클릭 발사 후 화면 이탈 실패, 클릭으로 재시작 후 초기 배치 복원을 확인하고 Play를 종료했다.
- 100회 이동은 고정 간격 실제 게임 코드의 자동 검사다. 실제 사용자 입력으로 100회 연속 성공한 기록은 아니며, 모바일 기기 빌드와 실측 성능 검증은 실행하지 않았다.
