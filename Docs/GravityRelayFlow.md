# 시작·플레이·결과 흐름 (2026-10-31)

## 화면

- 시작: GRAVITY RELAY, 최고 점수, 자동 공전/클릭·터치·Space 발사/금색 링 착륙 안내, START 버튼. 맵은 준비된 상태로 멈춰 있다.
- 플레이: 현재 점수, BEST 최고 점수, 다음 목표, 비행·포획 안내를 표시한다. 클릭/터치/Space로 발사하고 R로 즉시 새 게임을 시작한다.
- 결과: RUN OVER, 실패 사유, YOUR SCORE, BEST, 신기록이면 NEW BEST!, RESTART 버튼과 TITLE 버튼. 실패 다음 화면 갱신에서 바로 표시하며 별도 대기 애니메이션이 없다.

Enter/Space/R 또는 게임패드 South 버튼으로 시작·결과 화면에서 시작/재시작할 수도 있다. 플레이 중 게임패드 발사는 기존 Attack 바인딩을 따른다. 결과 화면에서는 아무 곳을 누르는 대신 RESTART 버튼으로 새 게임을 시작한다.

## 입력 분리

게임 이동을 멈추는 플래그와 Start/Playing/Results 화면 상태를 분리했다. 메뉴에서는 발사 액션을 실행하지 않는다. GUI 버튼은 누름/뗌으로 처리되고 화면 전환 후에는 해당 입력이 완전히 끝날 때까지 발사를 차단한다. 마우스·터치·키보드·게임패드 모두 새 누름부터 발사하며, 버튼을 누른 동작이 발사나 연속 재시작으로 재사용되지 않는다.

메뉴 버튼과 게임 입력에 별도 대기 시간을 넣지 않는다. 전환 입력 해제와 다음 프레임만 기다린다. 실제 포인터 발사는 카메라의 플레이 영역 안에서만 받는다. 타이틀로 돌아가거나 재시작해도 씬을 다시 로드하지 않는다. 기존 행성 풀과 시드를 초기화하고 UI 상태/예약 발사/순간 연출을 정리한다.

## 최고 점수

Unity PlayerPrefs의 `GravityRelay.BestScore.v1` 정수 키에 로컬 최고 점수를 저장한다. 시작 시 불러오며 신기록이 나면 메모리와 PlayerPrefs 값을 갱신한다. 실패, 새 게임/타이틀 전환, 앱 일시정지·포커스 이탈·종료, UI 비활성화 시 변경분을 디스크에 저장한다. 점수 증가 프레임마다 디스크 저장을 반복하지 않는다.

게임 시작 당시 최고 점수보다 이번 결과가 높으면 NEW BEST!를 표시한다. 점수가 같은 경우 신기록으로 표시하지 않는다. 네트워크 연결이나 별도 계정은 사용하지 않는다.

## 씬 구성과 작업 범위

기존 Relay Input and HUD의 RelayPresentation이 화면과 입력·기록을 담당하고, BCSD Player의 RelayPlayer가 실제 이동 실행 여부를 관리한다. 기존 씬 참조를 그대로 사용하므로 새 Canvas/EventSystem/프리팹이나 패키지가 필요하지 않다. 기존 물리값·난이도·행성 생성 구조는 변경하지 않았다.

사용자 요청대로 테스트·Play·빌드/컴파일 검사를 실행하지 않았으며, 별도 검증 코드도 추가하지 않았다. 열려 있는 에디터에는 수정 스크립트를 반영하고 GravityRelay 씬을 열면 시작 화면부터 진입한다.
